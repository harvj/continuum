## Extraction limits and migration risks

The export accounts for 37 records, not proof of every live-site resource.
JavaScript-generated content/images, external stylesheets and omitted export
content require comparison with source evidence. CSS extraction uses heuristics;
complex CSS and srcset syntax need review. Readable text normalizes whitespace;
serialized XML can change namespace prefixes. Original export bytes remain the
authoritative source. Multiple exports are not reconciled or deduplicated.

Attribution/creator metadata may survive in item XML but is not a dedicated
inventory field. Missing metadata must remain unknown. No reliable conversation
segmentation or human/AI role attribution has been established. Published source
HTML must be sanitized for rendering while retaining its untouched original.

Downloader canonicalization requests Squarespace `format=original`; it cannot
prove that upstream returns the highest-quality historical original. MIME headers
and local checksums do not establish image validity, attribution rights or website
completeness. There is no independent upstream checksum. Manifest reruns rebuild
from current exports, so removed references can disappear from the manifest even
though files are not deleted: archive prior manifests before changing source sets.
Safe additive reconciliation is required for the Rails importer.
